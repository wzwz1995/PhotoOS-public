# 设置、库管理与诊断

最后更新：2026-10-18 · 对应实现：`api/app.py`（`/api/data-root*`、`/api/libraries`、`/api/maintenance/migrate`、`/api/diagnostics`）、`web/js/app.js`

---

## 1. 数据根（`/api/data-root`）

桌面版的数据库、缩略图、备份都放在"数据根"里。打包版**默认** `%LOCALAPPDATA%\PhotoOS\data`，
用户的旧库可能在别处，所以界面上必须能看见、能切。

| 接口 | 作用 |
|---|---|
| `GET /api/data-root` | 当前数据根、库数、照片数、schema、是否可写 |
| `POST /api/data-root/validate` | 校验候选目录：`is_dir` / `has_db` / 库数 / 照片数 / 原因 |
| `POST /api/data-root` | 写入 `%APPDATA%\PhotoOS\desktop.json` 的 `dataRoot`，**下次启动生效** |

三条设计约束：

1. **不热切**：当前进程已打开旧库连接与后台线程，热切会让两个库同时被写。
2. **切之前必须校验**：`mode=existing` 要求目录里有 `photoos.db`；`mode=create` 要求目录里**没有**；
   两者都不满足返回 400。
3. 写的是**壳读的那份配置**（`app.getPath('userData')` = `%APPDATA%\PhotoOS\desktop.json`），不是另造一份。

界面位置：维护页 →「数据根」组；桌面壳里多一个「选目录…」（系统选择器）。

## 2. 添加照片库（`POST /api/libraries`）

界面：照片库标题旁「+ 添加…」→ 对话框（目录 / 名称 / 是否写标记）。

四种结论都走同一个接口：

| `probe_path` 结论 | 行为 |
|---|---|
| 新目录 | 建库；默认写 `<库根>\.photoos\library.json` |
| 已存在且 `reuse` | 复用，更新路径提示，不新建 |
| 换盘 `rebind` | 复用 + 状态置回 `ONLINE` |
| 目录不可访问 | 400，不建库 |

`.photoos` 标记是 PhotoOS **唯一**写进照片目录的东西；对话框里可关闭（`write_marker=false`）。

## 3. 一键迁移（`POST /api/maintenance/migrate`）

顺序固定：

```
完整性检查（复用 /api/integrity 的能力）
  → 备份 backups/photoos_before-migrate_<时间戳>.db
  → apply_migrations(..., make_backup=True)     # 失败由 migrator 自行回滚
  → 校验：版本不倒退 + asset/selection/shot/scene/library 计数不回退
  → 任一不过 → ok=false，列出 regressions 与备份路径
```

界面：维护页 →「数据维护」→「立即迁移」，显示 `版本 before → after` 与备份路径。

**已验证**：已是最新版本时幂等通过（`9 → 9`、`applied=[]`、备份生成、计数不变）。
**未验证**：真正跨版本升级。实验证明"删掉 `schema_migrations` 里的记录"**不会**让迁移重跑 ——
`ApplyResult.from_version` 仍是 9，说明版本来源不是该表的 `MAX(version)`。要做有效实验需要先读
`db/migrator.py` 的版本判定逻辑，或用单测覆盖。

## 4. 诊断信息（`GET /api/diagnostics`）

维护页「库状态」下方，一行行显示：版本与 schema、数据根、数据库路径与大小、服务地址、日志目录、
库数/照片数、AI 解释器是否配置。「复制诊断信息」把它拷成纯文本，方便发给维护者。

**刻意不含**照片路径与文件名 —— 诊断信息应该能安全地贴出来。

## 5. 绿色包的一个必须知道的行为

Electron 默认单实例：复制多份解压包，**同一时间只能运行一份**（共用 `%APPDATA%\PhotoOS` 的锁）。

实测从 `C:\PhotoOS-test\...` 启动时若已有实例在跑，会看到：

```
[ERROR] net\disk_cache\cache_util_win.cc: Unable to move the cache: 拒绝访问。(0x5)
```

然后进程退出。要并行测多份，用独立用户目录：

```
PhotoOS.exe --user-data-dir=C:\PhotoOS-test\userdata
```
