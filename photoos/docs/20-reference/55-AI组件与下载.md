# AI 组件与按需下载

最后更新：2026-10-18 · 对应实现：`photoos/ai_components.py`、`photoos/ai_install.py`、`photoos/ai_mirrors.py`、`photoos/library/model_store.py`

---

## 1. 先说边界：两个向量空间，两种"搜索"

这是本项目最容易写错的一处，先钉死：

| 能力 | 引擎 | 维度 | 依赖 | 能不能随包 |
|---|---|---|---|---|
| 相似照片 / 以图搜图 / 连拍归组 | **CLIP 视觉塔**（ONNX） | 512 | onnxruntime | ✅ 一键下载 335 MB |
| **用中文找照片** | **EmbeddingGemma2**（torch） | 768 | torch + 模型 | ❌ 外挂，4.3 GB |
| 人脸检测与识别 | YuNet + SFace（ONNX） | 128 | opencv + onnxruntime | ✅ 一键下载 37 MB |

**CLIP 的文本塔在现有代码里没有被调用**：`ClipOnnxEmbedder` 只提供
`embed_images / embed_paths / embed_arrays`，没有任何文本编码接口。
所以"CLIP 装好就能用文字搜照片"是错的 —— 那是 Gemma 的事。

> 2026-10-18 实测纠正：曾按"CLIP 文本塔 = 文字搜索"加过一个 242 MB 的组件，
> 核对 `library/embedding.py` 后确认无调用方，已从组件表移除。

## 2. 组件清单

定义在 `ai_components.COMPONENTS`，字段：`id / label / kind / size_mb / module|files / unlocks / requires / note`。

| id | 名称 | kind | 体积 | 依赖 | 装完解锁 |
|---|---|---|---|---|---|
| `onnxruntime-cpu` | ONNX Runtime（CPU） | pip | 15 MB | — | 视觉嵌入与人脸推理的运行时 |
| `clip-model` | CLIP 视觉塔 | model | 335 MB | onnxruntime-cpu | 相似照片 / 以图搜图（512 维） |
| `opencv` | OpenCV headless | pip | 55 MB | — | 人脸检测与识别 |
| `face-models` | YuNet + SFace | model | 37 MB | opencv | 人物页 |
| `onnxruntime-gpu` | ONNX Runtime（GPU） | pip | 231 MB | 本机 CUDA/cuDNN | 同上，走 GPU |
| `gemma-text` | EmbeddingGemma | **external** | 4.3 GB | torch | 用中文搜照片（768 维） |

规则：

- `requires` 没满足的组件在 UI 上是**灰的**，并写明"需要先装 X"
- `kind=external` **不提供一键安装**（接口返回 400 + 一句人话），避免用户误点 4.3 GB
- 组件**默认都不装**；不装不影响导入、索引、缩略图、精选、主题

## 3. 装在哪里

`ai_components.writable_install_dir()` 按顺序选：

1. 当前解释器的 `site-packages`（绿色包 = `runtime\python\Lib\site-packages`）—— 可写就用它
2. 不可写（例如装在 `Program Files`）→ `%LOCALAPPDATA%\PhotoOS\pylibs`

模型不装进 Python 目录，统一放 **`<data_root>\ai_cache\models\`**，跟库一起走，换机不用重下。

## 4. 下载与校验

### pip 组件

```
pip install <req> --target <dir> --only-binary=:all: --index-url <镜像>
```

`--only-binary=:all:` 是硬要求：用户机器没有编译器，任何需要现场编译的包
都会得到一句看不懂的错误，不如直接失败。

### 模型组件

复用 `library/model_store.py` 的 `fetch()` / `fetch_face()`：

| 环节 | 做法 |
|---|---|
| 已完成判定 | 字节数 + sha256（视觉塔、人脸模型都有官方值） |
| 下载 | 先写 `<file>.part`，完成后**原子改名** |
| 断点续传 | 有 `.part` 时带 `Range` 请求 |
| 校验失败 | 删除文件并抛错，不静默接受 |
| 无 sha256 的文件 | 兜底：**能否被 onnxruntime 打开**（文本塔曾用此规则） |

`fetch()` **失败时不抛异常**，而是返回 `ok=False` 的 `CheckResult` 列表 ——
调用方必须逐条检查，否则会出现"state=done 但一个文件都没下"。

## 5. 安装成功的判据（踩过三次坑）

> **"pip 返回 0" ≠ "装好了"；"下载完成" ≠ "能用"。**

`POST /api/ai/components/{id}/install` 的结束条件：

1. pip/下载环节无错误
2. **回读能力**：
   - `onnxruntime-cpu` → `import onnxruntime` 成功且 providers 非空
   - `onnxruntime-gpu` → `CUDAExecutionProvider` 必须在 providers 里
   - `clip-model` → `model_store.is_ready()`
   - `face-models` → `model_store.is_face_ready()`
3. 不满足 → `state=error` + 可操作的原因

### GPU 版的回滚

`onnxruntime-gpu` 在缺 CUDA/cuDNN 的机器上**不报错**，只静默提供 CPU provider。
因此安装流程固定为：

```
卸载 onnxruntime → 装 onnxruntime-gpu → 回读 providers
  ├─ 有 CUDAExecutionProvider → 成功
  └─ 没有 → 卸 GPU 版、装回 CPU 版、state=error
        "GPU 版装上了但没有 CUDA provider（通常是本机缺 CUDA/cuDNN 或驱动过旧）。
         已回滚到 CPU 版；CPU 版功能完全一致，只是慢一些。"
```

## 6. 镜像

两个独立配置，落在 `data/config.json`（不属于 `Settings` 的业务字段）：

| 键 | 默认 | 用在哪 |
|---|---|---|
| `pip_index_url` | `https://pypi.tuna.tsinghua.edu.cn/simple` | pip 装 wheel |
| `model_base_url` | `https://hf-mirror.com` | 模型下载（`model_store` 的 `*_DEFAULT_BASE_URL` 优先） |

- 只接受 `http(s)`，`file://` / 本地路径一律拒绝（否则"下载"变成"读本地"，sha256 校验失去意义）
- 每个镜像都有「测试」按钮：发 `Range: bytes=0-0` 请求，只看是否可达（`ai_mirrors.probe`）

## 7. HTTP 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/ai/components` | 组件清单 + 状态 + 当前镜像 + 安装目录 + providers + 安装任务状态 |
| POST | `/api/ai/components/{id}/install` | 触发安装，**立即返回**；进度靠轮询上一个接口的 `job` 字段 |
| POST | `/api/ai/mirrors` | 保存镜像（非 http 返回 400） |
| POST | `/api/ai/mirrors/test` | 连通性测试 |

安装跑在 `asyncio.to_thread` 里，状态存进程内存（`running/done/error` + 最近 40 行日志），
**不新增任务引擎**，也不阻塞请求线程。

界面：维护页「AI 组件」折叠组（列表 / 体积 / 依赖灰化 / 安装按钮 / 实时日志 / 镜像输入 + 测试）。
「找照片」页空态提供「一键准备」，按依赖顺序装 `onnxruntime-cpu` → `clip-model`。

## 8. 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 下载卡住 / 超时 | 镜像不可达 | 点「测试」换镜像；`hf-mirror.com` 与官方 `huggingface.co` 都支持 |
| 装完状态仍"未装" | 进程 import 缓存 | 已修：探测前 `importlib.invalidate_caches()` |
| 装完状态"未装"（模型） | 文件不齐 / 校验不符 | 看 `job.log` 最后几行；重新点安装（会续传） |
| GPU 版装了但很慢 | 没有 CUDA provider，静默用 CPU | 看 `/api/ai/components` 的 `providers`；缺 CUDA 就用 CPU 版 |
| 安装目录不可写 | 装在 `Program Files` | 自动退到 `%LOCALAPPDATA%\PhotoOS\pylibs` |
| 磁盘不够 | 模型 4 GB 级 | 先看 `ai_install.free_space_gb()`；组件表里有体积 |
| 语义搜索仍然灰 | 只装了 CLIP，没有 Gemma | 中文文字搜索需要 `gemma-text`（外挂 4.3 GB） |

## 9. 实测记录（2026-10-18，本机）

| 项 | 结果 |
|---|---|
| `onnxruntime-cpu` 安装 | pip 装进 `site-packages`；providers = `Azure/CPU`；单张 224×224 推理 **28 ms** |
| CLIP 视觉塔 | 335.4 MB（351,685,709 B，sha256 `fd6e1402…`）下载 **10 s**；加载 0.65 s；输出 `(1, 512)` |
| `opencv` | `cv2 5.0.0`，安装约 9 s |
| 人脸模型 | YuNet 0.2 MB + SFace 36.9 MB，sha256 校验通过，`is_face_ready=True` |
| `onnxruntime-gpu` | 装完无 CUDA provider → **自动回滚** CPU 版，`state=error` 并给出原因 |
| 误建的 CLIP 文本塔 | 242 MB，**已移除**（代码无文本编码接口） |

**未验证**：真实照片上的以图搜图排序质量、Gemma 中文搜索的端到端效果、
干净 Windows 机器上的完整流程。
