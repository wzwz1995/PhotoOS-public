# 中文语义搜索（EmbeddingGemma）的安装

最后更新：2026-10-18 · 对应实现：`ai_components.py`（`kind="venv"`）、`ai_install.py`（`ensure_ai_venv` / `install_into_venv`）、`api/app.py`（安装路由）、`library/model_store.py`（`fetch_gemma`）

---

## 1. 它解决什么，和 CLIP 什么关系

| 能力 | 引擎 | 维度 | 说明 |
|---|---|---|---|
| 相似照片 / 以图搜图 | CLIP 视觉塔 | 512 | 图像到图像；**不做文字** |
| **用中文找照片** | **EmbeddingGemma2** | 768 | 中文搜索的**唯一**引擎 |

`photoos search --help` 明写：`--engine {gemma}` —— **CLIP 的中文实测失效**，
检索不经过 CLIP。早期文档里"CLIP 文本塔"的说法是错的（代码里也没有文本编码接口）。

## 2. 为什么不随包分发

| 组成 | 体积（实测） |
|---|---|
| torch（CPU 版 wheel）+ sentence-transformers + 依赖 | **995 MB**（torch 2.14.1+cpu，st 6.1.0） |
| 模型 `model.safetensors`（fp32） | **1,419.9 MB**（1,488,915,288 字节） |
| 合计 | **≈ 2.45 GB** |

塞进安装包会把 233 MB 的绿色包变成 5 GB 级；而且 torch 的 CPU/CUDA 轮子互不通用，
升级时容易互相踩。所以做成**安装时落到独立 venv**。

## 3. 装在哪里

```
%LOCALAPPDATA%\PhotoOS\ai-venv\          独立 venv（含 pip、torch、sentence-transformers）
<data_root>\ai_cache\models\embeddinggemma-2-safetensors-fp32\
    model.safetensors                    1.42 GB（校验：字节数 + sha256）
    tokenizer.json / tokenizer.model / tokenizer_config.json / modules.json ...
```

装完把 `config.json` 的 **`ai_python`** 指向 `ai-venv\Scripts\python.exe` ——
这是项目里"AI 用什么解释器"的唯一开关。

**失败不留半装状态**：venv 或下载失败时删掉 `ai-venv` 与不完整模型文件即可重来；
`fetch_gemma` 自身先写 `.part` 再校验改名。

## 4. 安装流程（一键）

```
设置 → AI 组件 → 「中文语义搜索（EmbeddingGemma）  4300 MB」
  → 点「安装」（先弹确认：约 4300 MB / 十几分钟 / 同等磁盘）
  → 1. ensure_ai_venv()            建 venv（已有则复用）
  → 2. install_into_venv()         venv 的 python -m pip install torch sentence-transformers
                                   （--only-binary=:all:，走用户配置的 pip 镜像）
  → 3. model_store.fetch_gemma()   下载模型（走模型镜像，Range 续传，字节数 + sha256）
  → 4. is_gemma_ready()            复核
  → 5. 写 ai_python
```

进度：后端把每个阶段的日志塞进 `job.log`，前端每 2 秒轮询 `GET /api/ai/components` 显示。

## 5. 镜像

| 层 | 配置键 | 默认 |
|---|---|---|
| pip（torch 等） | `pip_index_url` | 清华 TUNA |
| 模型 | `model_base_url` | `hf-mirror.com`；Gemma 实际走 `model_store.GEMMA_DEFAULT_BASE_URL`（modelscope） |

## 6. 代价与权衡

| 项 | 数值 |
|---|---|
| 下载量 | **≈ 2.45 GB**（实测，比原估的 4.3 GB 小） |
| 磁盘占用 | **≈ 2.45 GB**（venv 995 MB + 模型 1.46 GB） |
| 耗时 | 实测 **319 秒（约 5.3 分钟）**，含 torch 安装与模型下载 |
| CPU vs GPU | 默认装 **CPU 版 torch**；本机也可选装 `torch-cuda` 组件（CUDA 13 轮子） |
| 内存 | 加载模型常驻约 1–2 GB |

### 6.1 CUDA 加速（可选组件 `torch-cuda`）

2026-10-21 实测：

```text
AI venv: C:\Users\user\AppData\Local\PhotoOS\ai-venv
torch 2.14.1+cu130 / torchvision 0.29.1+cu130
torch.cuda.is_available() = True
GPU: NVIDIA GeForce RTX 3060 Laptop GPU（6144 MiB，驱动 581.57，CUDA 13.0）
```

- `photoos embed --engine gemma --dry-run` 显示 `cuda，234.2 ms/张`；
- CPU 同口径约 `4,918 ms/张`；
- 6,737 张待补：GPU 约 **26 分钟**（按实测 234 ms），CPU 约 **9.2 小时**；
- GPU 占用接近 6 GB（模型 + batch 8 + 桌面其他程序），显存紧张时先关掉占用 GPU 的程序，或把 batch 降到 4；
- **ONNX Runtime GPU 不是这个组件**，它只服务 CLIP / 人脸。

组件安装入口在「维护 → AI 组件 → EmbeddingGemma CUDA 加速（torch）」；
装完在组件状态里回读 `torch.cuda.is_available()`，不是只看 pip 成功。

## 7. 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| pip 阶段超时/失败 | 镜像不可达或没有对应 wheel | 换 `pip_index_url`；确认是 `--only-binary` 能满足的轮子 |
| 装完 `import torch` 失败 | 缺 VC++ 运行库 / 轮子与 Python 版本不匹配 | 用 venv 的 python 手动跑一次 `-c "import torch"` 看报错 |
| 模型下载卡住 | 镜像慢 | 换 `model_base_url`；`fetch_gemma` 支持续传，重试即可接着下 |
| 校验失败 | 文件不完整 | 会删掉重下；反复失败就手动删除该目录 |
| 组件显示"未装"但文件都在 | `ai_python` 没写成功 | 检查 `config.json` 的 `ai_python` 是否指向 `ai-venv\Scripts\python.exe` |

### 验证通过的完整链路（2026-10-18 实测）

```
1. AI venv: torch 2.14.1+cpu / sentence-transformers 6.1.0 / transformers 5.20.1
             / torchvision 0.29.1+cpu / requirements.lock 的 16 个运行时依赖
2. 模型: Gemma 13 个文件（含 1_Pooling/config.json、2_Normalize/config.json）
3. 导入照片
4. photoos shots regroup --apply && photoos scenes rebuild --apply   ← **前置步骤**
5. photoos embed --engine gemma --apply        → 20/20
6. photoos search "日落" --save                 → 11 条命中（相似度 0.58–0.61）
```

**最容易踩的坑**：跳过第 4 步时搜索永远返回"没有找到任何结果" ——
搜索按拍摄组返回，没有 Shot 就没有搜索池。这与模型是否装好无关。

> 验证方式：在临时目录跑完整链路（`%TEMP%\gemma-probe-*`），
> **不写正式 `config.json`、不碰 `%LOCALAPPDATA%\PhotoOS`、不动正式库**。
> 结果补齐后更新本表。
