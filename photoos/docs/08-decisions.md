# 08 · 关键决策与踩过的坑

> 这一篇记的是**为什么是这样**，以及**不能改成什么样**。
> 每一条都尽量附上"怎么发现的"——因为只写结论的文档，下一个人会把结论推翻。

---

## 一、令牌归一：从两处定义到一处（2026-10）

### 症状

同一个应用里出现**三种"当前项"长相**、**两种蓝**、**六种圆角**、**四种焦点环**，
两处 UI 字体掉出品牌字体栈。

### 根因

设计令牌被**定义了两遍**：

- `app.css` 的 `:root` 一套默认蓝（`--accent: #4c8dff` 等）；
- `phase2.css` 又在 `body` 上覆盖一遍，靠 **"body 比 :root 更靠内"** 压过前者。

同一批变量名定义两次，谁生效取决于**文件加载顺序**与**选择器层级**两件互不相干的事。
它能工作，纯属当时那两张表的加载顺序恰好正确。

### 用计算样式量出来的实际代价

用 CDP 驱动无头 Chrome 逐页取 `getComputedStyle`：

| 项 | 实测 |
|---|---|
| 同一个"当前项" | `.tab` 灰底描边(8px) / `.seg` 蓝底实心(5px) / `.find-mode` 金下边 |
| 同一个"激活" | `.seg.is-active` = `rgb(30,77,170)`，`.btn.primary` = `rgb(10,36,99)` |
| 字体掉栈 | `.tab`/`.seg`/`.browse-node` = **Arial**；`code`/`.output` = 通用 **monospace** |
| 圆角 | 3/4/5/6/8/999px（分级只有 4/8/12/20） |
| 焦点环 | `rgba(10,36,99,.55)` / `rgba(30,77,170,.55)` / `--focus` / 缺失 |
| 对比度 | `--ink-text-3` 只有 **3.70:1**，低于 WCAG AA 的 4.5:1 |
| 页面宽度 | 1600px 视口下主题页只用 700px，右侧 900px 全空 |

### 决定

新增 `web/css/tokens.css` 作为**唯一**令牌定义处，**第一个加载**；
`app.css` 不再有自己的 `:root`；旧变量名降级为兼容别名（保留但新代码不得使用）。

### 不能改回去的地方

- **`tokens.css` 必须第一个加载。** 顺序反了不报错，只会静默拿到未定义变量。
  有测试守着（`test_tokens_load_before_every_other_stylesheet`）。
- **令牌不得在别处再定义。** 有测试扫描全部 CSS，只允许 `tokens.css` 出现 `--royal-700:`。

## 二、`max_retries = 0` 被读成 3（2026-10）

```python
max_retries=int(row["max_retries"] or 3)   # ← 0 or 3 == 3
```

`0` 是**有意义的取值**（"不重试"），但 `or` 把它当假值吃掉了。
后果：任何显式传 `max_retries=0` 的任务，失败后仍会重跑 3 次。

**怎么发现的**：给界面直跑命令设 `max_retries=0` 之后，任务表里同一条命令
失败 4 遍，每次都完整重跑一次环境探测。先怀疑是自己的新代码，加了调用追踪才定位到
读取层。

**修法**：判 `None` 而不是判假值。

```python
max_retries=int(row["max_retries"]) if row["max_retries"] is not None else 3
```

**教训**：`x or default` 只适用于"假值恒等于未设置"的场景。**计数、开关、枚举的 0
都是有意义的**，这条例子在别处也值得再审一遍。

## 三、白名单命令目录里写了一条不存在的命令（2026-10）

界面加"直接执行"能力时，我凭印象写了 `photoos search --list` 当作"列出已准备的搜索词"。
`search` 子命令**根本没有 `--list`**，按钮点下去返回 `unrecognized arguments`。

**为什么肉眼审不出来**：命令是字符串，写错了不会有任何静态错误。

**修法**：加了一条契约测试，拿**真的 argparse parser** 逐条解析目录里的每条命令
（`tests/unit/test_actions_catalog.py`）。同时把那条假命令换成真实存在的 `stats`。

**教训**：凡是"数据里嵌了外部接口的名字"（命令、参数、路由、表名），
都应该有一条拿真解析器验证的测试。

## 四、界面直跑命令的安全边界（2026-10）

### 需求

界面上原本有六处"这件事我算不了，请你去命令行跑一次"。用户要的是**点一下就能跑**。

### 诱惑与风险

最省事的做法是提供一个"执行任意命令"的接口。**没有这样做**：服务监听
`127.0.0.1:8760`，本机上任何能发 HTTP 的东西（包括浏览器里任何一个页面，
通过 CSRF 或 DNS rebinding）都能打到它 —— 那等于把本机 shell 交出去。

### 采用的边界

- 命令**只**在服务端 `actions/catalog.py` 里以固定 `argv` 模板定义；
- 浏览器**只能提交一个 action id**，不能提交命令字符串；
- 唯一进入命令行的用户输入是搜索词，走字符白名单 + 长度上限，
  且**始终作为单独一个 argv 元素**传递，不走 shell（`shell=False`）；
- 未知 id → 404；非法搜索词 → 422。

有测试逐条断言一串注入样本（`;`、`&&`、`|`、`$()`、反引号、换行、超长）必须被拒，
并断言模板里不含任何 shell 元字符。

### 不能改回去的地方

- **不要引入 `shell=True`。**
- **不要接受浏览器传来的 argv。**
- 加新命令时**必须**同时过 `test_every_catalog_command_is_accepted_by_the_real_cli`。

## 五、服务端与 AI 环境是两个解释器（2026-10）

### 现象

截图里那条提示：搜索要算文本向量，但"这个页面所在的环境没有装它"，
命令行给的是 `C:\PhotoOS\venv\Scripts\python.exe` —— 一个**别的 venv**。

### 根因

`pyproject.toml` 把 torch / onnxruntime / opencv 放在**可选依赖**里
（`[ai-cpu]` / `[ai-gpu]` extra），产品 venv 按设计不装。而 EmbeddingGemma
**没有 ONNX 产物**（官方仓库就没有），所以它必须走 torch，
无法退化成 onnxruntime 路径。

于是"服务在 A 环境、模型在 B 环境"成了常态。

### 决定

新增配置 `Settings.ai_python`（`data/config.json` 的 `ai_python`，或环境变量
`PHOTOOS_AI_PYTHON`）。界面直跑的命令用这个解释器执行；留空则用服务自身的。
界面上的**执行环境**一栏会明确写出"用的是哪个 python、为什么"。

### 实测效果

| | 未配置 `ai_python` | 配置为 `venv` |
|---|---|---|
| 缺失依赖 | `torch, sentence_transformers, onnxruntime, cv2` | `[]` |
| 准备搜索词 | 不可用（且失败信息清楚说明原因） | 可用 |
| 人脸检测/特征 | 不可用 | 可用 |

**没有**配置好时界面**不隐藏**这些命令，只标成"缺依赖"并说明装法 ——
藏起来的话用户永远不知道有这个能力。

## 六、`install.ps1` 缺 UTF-8 BOM（2026-10 修）

`packaging/install.ps1` 含中文，但文件没有 BOM。**Windows PowerShell 5.1 读没有
BOM 的脚本时会按系统 ANSI 代码页解码**，中文变成乱码，严重时直接语法错误。

测试其实一直在报这条（`test_packaging.py`），但它是**先于本次会话就存在**的失败
（文件最后修改时间比会话开始早）。已补上 BOM。

**教训**：仓库里的失败测试不要因为"不是我改坏的"就放着 —— 它会淹没新引入的失败。

## 七、深色界面是有意的偏离，不是破例

Feihong Console 场景规范默认浅色（暖米白 `#FDFBF6`）。本应用**全部内容**是
"看一眼照片然后判断"，浅色底会抬高周围亮度、影响对照片本身明暗与色彩的判断
（修图/选片工具几乎都是深色，同一原因）。

DNA 里本来就给了深色模式令牌（底色 `#0A0E1A` / 卡片 `#121828` / 分隔线 `#1E2740`），
且 Console 规范只禁止"3:4 图文卡片"用深色。所以这是**规范内的选择**。

三色语义、字体策略、圆角分级、阴影色相全部照守。

## 八、Inter 是有意保留的

通用审美检查会把 Inter 标成"烂大街的字体"。这里**有意保留**：它是本项目既定
设计系统（Feihong DNA 字体策略）明文要求的 UI 字，字体文件已本地化为 woff2。

换字体会同时推翻品牌规范与"零外网请求"两条硬约束，收益只是回避一条通用告警。
理由已写在 `tokens.css` 里，免得下一个人再来问一遍。

## 九、对比度是量出来的，不是看出来的

深色界面上"看起来还挺清楚"的灰字，实测只有 3.70:1。用 CDP 逐页算 WCAG 对比度后
发现 14 处不达标（顶栏状态行、说明页目录、照片库统计标签、找照片表单标签）。

修法不是统一调亮一个值就完事，而是**按语义分层**：

- 最弱一级 `--ink-text-3`：`#6b7288` → `#7d849b`（4.93:1）；
- **要读的内容**（页面副标题、表单标签、统计标签、目录项）从 `--ink-text-3`
  升到 `--ink-text-2`。

现在七页 0 处不达标。

**教训**：颜色对比度必须用公式量。人眼在深底上对灰字的判断非常不可靠。

## 十、不做"评分/推荐"（产品底线）

PRD §9.2 LOCKED：禁止"AI 替用户选择"。落在界面上：

- 没有星级、没有进度环、没有"匹配度 87%"的大字；
- 相似度**刻意做得极小且灰**（`--ink-text-3`），作用是"为什么它在前面"的可核对性，
  不是给人比优劣的；
- 金色 = "**你的选择 / 当前项**"，**不是"更好"**；
- 酒红 = 危险/否决，**不是"更差"**；
- 状态徽标只表达"你把这张放到哪一档"，不表达好坏。

新人最常犯的错是给"最终精选"加上更亮的颜色或更大的字来表达"这是最好的"——
那正是这条禁令要防的。

### 边界规则（最容易出错的一条）

| 情境 | 用什么 | 为什么 |
|---|---|---|
| "这几张我**正挑着**" | **皇家蓝**环 | 进行中的状态，不是判断结果 |
| "我已经把这张**留下了**" | **金**框 | 判断结果 |
| "已删掉" | 酒红框 + 压暗 | 也是"你把这张放哪儿"，不表达好坏 |

两者混用会让"我选中了"和"我已经留下了"看起来一样 —— 那是会出错的。

## 十一、3px 左侧色条是本项目具名的禁忌

"卡片/提示/告警左侧的 3px 色条"被认为是**最容易被认出来的 AI 生成痕迹**，
在本仓库被**移除四次**：

| 位置 | 改成 |
|---|---|
| `.notice`（提示条） | 1px 同色描边 + 同色系淡底 |
| `.grp.is-active`（当前相似组） | 金色描边 + 淡底（与其他"当前项"同构） |
| `.person-profile`（模型学到了什么） | 皇家蓝描边 + 淡底 |
| `.asset-path` / `.pack-result`（原片位置） | 金色描边 + 淡底 |

Feihong Console 规范自己的 alert 槽位写的也是"1px 左边框 + 同色系淡底"，
所以这是**规范内**的选择，不是偏离。

**注意**：Feihong 的 Console 规范里另有一处"3px 金色指示条"用于**深色侧边栏的
导航选中项**（`§6.4`）。本仓库的顶栏当前页用的是 2px 金色下边框，与那一处不冲突 ——
真正被禁的是"卡片/提示块左侧的色条"，不是所有竖条。

**改代码时**：删掉的是那四处装饰性色条；不要顺手去动导航的选中指示。
