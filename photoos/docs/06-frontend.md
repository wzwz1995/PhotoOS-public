# 06 · 前端与设计系统

前端是**零构建**的：原生 CSS + 原生 ES module，没有 npm、没有打包步骤、没有框架。
浏览器直接加载 `web/` 目录里的源码，改完刷新即可见。

目录：`index.html` + `css/*.css` + `js/*.js` + `fonts/*.woff2`。

---

## 一、加载顺序与分层

```html
tokens.css   ← 必须第一个
app.css      基础层：骨架、顶栏、侧栏、网格容器、控件兜底
phase2.css   组件层：页头、控件、按钮、空态、徽标、页面节奏 + 精选/主题
modal.css    弹窗
search.css   找照片
people.css   人物
help.css     说明
```

### 唯一的一条硬规则

> **设计令牌只在 `tokens.css` 里定义一次，且它必须第一个加载。**
> 其余六张表只**消费**令牌。

为什么强调：改前令牌定义了**两遍**（`app.css` 的 `:root` 一套默认蓝，
`phase2.css` 在 `body` 上再覆盖一遍），谁生效取决于**文件加载顺序**与
**选择器层级**两件互不相干的事。实测代价：同一个"当前项"三种长相、两种蓝、
`.tab`/`.seg` 掉到 Arial、六种圆角、四种焦点环。
见 [`08-decisions.md`](08-decisions.md) 第一节。

有测试守着这条（`test_tokens_live_in_exactly_one_file`、
`test_tokens_load_before_every_other_stylesheet`）。

### 分层归属

| 文件 | 拥有什么 |
|---|---|
| `tokens.css` | 全部令牌 + `@font-face`（4 个字重）+ 页面底色（`body` 的底色与右上角径向微光） |
| `app.css` | 骨架、顶栏/`.tab`、侧栏、虚拟网格容器、任务与导入表、**控件兜底** |
| `phase2.css` | 组件契约、页面节奏、`.view-head`、`.btn`（**权威几何量**）、全局表单控件、`.sel-badge`、`.wb-empty`、`.cmd-block`、`.act-*`、精选/主题 |
| `modal.css` | `.wb-modal`（选片弹窗）、`.asset-modal`（原片弹窗）、`.pack-result` |
| `search.css` / `people.css` / `help.css` | 各自的 `.*-` 前缀 |

> `@font-face` 原先在 `phase2.css` 顶部，而 `--font-*` 令牌在 `tokens.css` ——
> 字体文件与引用它的令牌分居两个文件。2026-10 一并搬到 `tokens.css`。
> 同时删掉了 `web/fonts/brand-fonts.css`（内容完全相同的副本，从未被引用）。

## 二、设计令牌

设计系统：**Feihong Design System v8.0 · 场景 06 Console**。

### 三色基因（必须精确，不做近似）

| 色 | 值 | 语义 |
|---|---|---|
| 皇家蓝 | `#0A2463` | 导航与主操作、"你的操作"、进行中 |
| 复古金 | `#F4D35E` | 高亮、"**你的选择**"、当前项 —— **不表示"更好"** |
| 酒红 | `#D8315B` | 错误/危险/已否决 —— **语义色，不作装饰，一屏 ≤2 处** |

**语义路由表**（挑颜色前先读这张表）：

| 含义 | 用什么 |
|---|---|
| 当前项 / 我选中了 / 我的判断 | 金 `--gold-500` |
| 进行中 / 可点的动作 / 你的操作 | 皇家蓝 `--royal-300/400/500` |
| 错误 / 危险 / 你否决了 | 酒红 `--wine-400/500/600` |
| 中性 / 还没信息 / 机器内部数据 | `--ink-text-3`，**不给颜色** |

> **边界规则**（最容易出错的一条）：*"这几张我正挑着"* 是**进行中**，
> 用**皇家蓝环**；*"我已经把这张留下了"* 是**判断结果**，用**金框**。
> 两者混用会让"我选中了"和"我已经留下了"看起来一样 —— 那是会出错的。

### 其它令牌族

- **中性色**：`--ink-base/panel/panel-2/divider/line/text/text-2/text-3`，带蓝相不用冷灰。
  `--ink-stage #07090f` 是照片舞台（比面板更深，"让照片自己发光"）。
- **功能色**：`--ok`（绿，只用于"完成"）、`--warn`（琥珀，只用于暂停/警告）、
  `--fail`（= 酒红）、`--state-pending`。**不参与品牌表达。**
- **字体**：`--font-display`（Playfair Display）/ `--font-ui`（Inter）/ `--font-mono`（JetBrains Mono）。
  中文走系统栈 —— 不下载中文字体，运行时**零外网请求**。
- **字号**：七级 `--fs-2xs..--fs-lg` + 三个 clamp（`--fs-title/--fs-hero/--fs-kpi`）。
  新增文字请从这七级里挑。
- **圆角**：`--r-sm 4` / `--r-md 8` / `--r-lg 12` / `--r-xl 20` / `--r-pill`。
  **不新增第 6 级。**
- **间距**：`--sp-1..7`。
- **页面节奏**：`--gutter`（左右）/ `--flow`（块间距）—— 见第四节。
- **阴影**：全部是 `rgba(4, 15, 42, α)`，色相偏皇家蓝，**不用通用黑**。
- **焦点环**：`--focus` / `--focus-tight`，**全应用一套**。
- **动效**：`--ease: cubic-bezier(0.16, 1, 0.3, 1)` 一条缓动贯穿全应用；克制、不弹跳。
- **下拉箭头**：`--chevron`（内联 SVG），因为 `appearance: none` 之后所有 select
  都失去了"这是下拉框"的提示。
- **控件高度**：`--control-h: 42px` —— 输入框 / 下拉框 / 按钮的**唯一高度真源**。
  三者一律 `height: var(--control-h)` + `box-sizing: border-box`。
  改前是**两个真源**（输入框 `min-height: 38px`、按钮由"行高 + 内边距 + 描边"
  算出 42px），并排时输入框比按钮矮 4px —— 用户报的"没对齐"就是这个。
  ⚠️ `textarea` **不共用**（多行控件钉成一行高会把输入区压扁），
  它只共享配色与描边，高度是 `calc(var(--control-h) * 1.6)`。
- **标签列宽**：`--wb-label-w: 96px` —— 表单里"标签在上、控件在下"那一族的
  统一标签行高。标签宽度靠内容撑时，标签一长一短控件起点就错开。
- **横排对齐**：`.row` 是 `align-items: flex-end` + 行内 `.field` 去掉纵向边距。
  **横排一律按底边对齐** —— 标签在控件上方时，各字段高度天然可能不同
  （标签可能换行），按顶边对齐会让控件高低错开。

### 两处有意的偏离（都有理由，别"顺手修好"）

- **深色而非 Console 默认的暖米白**：本应用全部内容是"看一眼照片然后判断"，
  浅底会抬高环境亮度、干扰对照片明暗与色彩的判断（修图/选片工具几乎都是深色）。
  DNA 本来就给了深色令牌，且只禁止"3:4 图文卡片"用深色 —— 属**规范内选择**。
- **Inter**：通用审美检查会把它标成"烂大街"。这里有意保留 —— 它是 DNA 明文要求的
  UI 字，且已本地化为 woff2；换字体会同时推翻品牌规范与"零外网请求"两条硬约束。

## 三、组件契约

七个标签页共用一套。**"当前项"只有两种画法**：

| 组件 | 用途 | 当前项的样式 |
|---|---|---|
| `.tab` | **切页**（顶栏） | 金色下边框 + 金字 |
| `.find-mode` | **页内模式**（找照片） | 金色下边框 + 金字（与 `.tab` 同一语义） |
| `.seg` | **页内维度**（照片库左栏） | 皇家蓝实心 |

> 三者分工是刻意的：`金 = 当前项`，`皇家蓝 = 进行中的操作`。
> 改前同一件事有三种长相、两种蓝。

| 组件 | 说明 |
|---|---|
| `.view-head` | 页头：衬线标题 + 右侧动作 + 一条分隔线。**七个视图都有** |
| `.panel` / `.panel.wide` | 面板。`h2` 用无衬线（衬线只留给页面大标题） |
| `.btn` | 基础按钮。变体：`.primary`（皇家蓝实心，**一个面板只有一个**）、`.gold`（金描边 = "你的选择"）、`.danger`（酒红 = 破坏性）、`.ghost`、`.small`、`.mark`（46px，主流程按钮）、`.quiet`（人物页的"不是人"，hover 才显酒红） |
| 表单控件 | 一条全局规则（`select`/`input[type=text/search/number/date]`）。**高度一律 `var(--control-h)`**，与 `.btn` 同源；`appearance:none` + `select` 加 `--chevron`。`textarea` 单独一条（多行，只共享配色与描边） |
| 复选框/单选 | **不用浏览器默认**：金底 + 皇家蓝勾，勾是两条边框画的（不引图标字体、不用 emoji） |
| `.sel-badge` | 精选四态徽标。四档**都只是"放到哪一档"，不表达好坏** |
| `.badge` / `.state` / `.person-tag` | 同一族胶囊。`.state` 七种任务状态**全**有样式 |
| `.wb-empty` | **全应用唯一**的空态组件。见下 |
| `.cmd-block`（别名 `.search-cmd`/`.people-cmd`/`.help-cli`） | "照抄这条命令"的代码块 |
| `.act-row` / `.act-env` | 界面直跑命令的列表行与环境说明 |
| `.toast` | 轻提示 |

### `.wb-empty` 的两种安放方式

它**自带边框**，所以按"被谁装着"分两态（由父选择器决定，没有修饰类）：

- **独立**（直接放在视图里）→ 保留边框与底色；
- **内嵌**（在 `.panel` / `.wb-modal-body` / `.review-main` / `.review-side` /
  `.person-section` 里）→ 去掉边框与底色。

改前混用，于是面板里出现"卡中卡"两层同色方框，看起来像没加载完的占位。

加载态是同一个壳子的变体（`.is-loading`，fleuron 呼吸），**没有转圈 gif、没有骨架屏** ——
本地服务几百毫秒就回来。

### `.cmd-block`：为什么换行必须那样写

命令里含解释器**绝对路径**，窄屏上很长。`pre-wrap` + `break-all` 会把它**硬切成几段**、
缩进全丢 —— 用户复制走的是半条命令。正确形状三者缺一不可：

1. `white-space: pre`（保留原始空白与缩进）；这几处的元素还带着 `hint` 类，
   而 `.hint` 是正文排版，所以必须在这里显式压回去；
2. `overflow-x: auto`（自己横向滚动）；
3. `word-break: normal` + `overflow-wrap: normal`（不在路径中间断词）。

**这个组件曾经在三个文件里各写一遍**，其中两处是坏的（只有找照片那处被修过）。
现在只有一处声明。

## 四、页面骨架

### 纵向 flex 规则

`app.css` 里 `.view.is-active { display: flex }` —— **没写方向，所以是横向**。
六个视图在 `phase2.css` 里被改成 `flex-direction: column`；
照片库单独处理（它天生是"左栏 + 内容"的横向两栏，强行改纵向会把网格挤出屏幕）。

### 节奏：`--gutter` / `--flow`

**每个视图的直接子块**统一吃左右 `--gutter` 与上下 `--flow`。
只有两个声明的例外：`.library-body`（两栏，各自管留白）与 `.review-layout`（自带 padding）。

改前实测：同一个精选页里页头内缩 28px、工具栏 20px、面板 margin 14px 而 padding 16px
—— 同页三种左边距；跨页更乱（照片库 14px、维护页 16px、说明页什么都不加）。

### 宽度策略：**工作区占满，长文限宽**

- 工作区（人物/主题/维护/精选/找照片）= 撑满可用宽度；
- 说明页是"给人读的" = 正文限可读行宽，但**整块居中**。

改前 `.panel.wide { max-width: 1100px }` 卡死所有页面：1600px 视口下主题页只用了
700px，右侧 900px 全空。

## 五、JS 模块架构

### 为什么有 `shared.js`

> `app.js` 在模块顶层会**立即启动应用**（`boot()`、轮询、事件绑定）。
> 因此别的模块**不能 import app.js** —— 那会在导入时把应用再启动一遍。

所以把无副作用的东西抽到 `shared.js`：`API`、`$`/`$$`、`loadingHtml`、`toast`、
`humanBytes`、`escapeHtml`、`baseName`、`parentPath`、`formatWhen`、精选状态工具。
纪律：**本文件不得有顶层副作用**（不查 DOM、不发请求、不绑事件）。

需要回到 `app.js` 时用**函数内**动态 `import('./app.js')`（有 5 处这样）。

### 按需加载

`setView()` → `activateLazyView(view)`（`app.js` 里一个 if/else 阶梯，不是注册表）
→ `await import('./xxx.js')` → 调该模块自己的 `initX()` + `refreshX()`。

**init 只跑一次，refresh 每次进入都跑**（各模块自己用布尔量守 init）。
`deactivateLazyView` 只处理 `review`（它要卸键盘监听）。

### 状态

每个模块一个模块级 `const state = {...}`，外面拿不到。
**没有 store、没有事件总线**（全仓库 `CustomEvent|dispatchEvent` 零匹配）。
通信只有四种：静态 import、动态 `import('./app.js')`、
唯一的全局 `window.photoosRefreshJobs`、以及 DOM 本身。

### 轮询

一条 4 秒的定时器刷新健康状态与任务表；导出另有一条 1.2 秒的跟踪循环（一小时上限）。
界面直跑命令用 `actions.js` 里自适应的轮询（800ms 起，×1.3 递增，上限 4s）。

## 六、三个已知布局陷阱（改 CSS 前必读）

这三条在本仓库反复出现，注释里都记着"怎么发现的"。

### 陷阱 1：`.view.is-active` 是**横向** flex

往 `<section class="view">` 里直接塞块，会变成"同一行里的列"，各自按内容宽度收缩
—— 屏幕上就是几根被挤扁的窄柱，文字一行只放得下几个字。

维护页曾经**漏在修正名单外**，被排成五根并排的窄柱（"导入新照片"只剩 150px 宽），
用 `getBoundingClientRect` 量出相邻面板间距是 **-951px**。

### 陷阱 2：`flex-shrink` 会把固定高度的子项压扁

`.view` 有固定高度（`height: 100%`），纵向 flex 的子项默认 `flex-shrink: 1`，
于是每个块**被压缩**去迁就容器高度。实测 `.wb-head` 被压到 40px，
里面的标题因为 `align-items: flex-end` + 裁切直接跑到 y = **-19**（负坐标，看不见）。

修法：子项一律 `flex: 0 0 auto`。

### 陷阱 3：flex 子项不会缩到比内容更窄

`.rebind` 那一行有三个控件，输入框的 placeholder 很长，
**没有 `flex-wrap: wrap` 时该行不肯缩到比"最长那一项"更窄**，
于是整行撑破面板、两个输入框各被拉到 1200px 宽并溢出到外面。

修法：容器 `flex-wrap: wrap`，可伸缩的那个加 `min-width: 0`。
同一模式也出现在卡片底栏（`.card .cap`）：必须 `nowrap` + 文件名省略号，
否则 1280px 下会折成两行。

### 附：第四个陷阱 —— `[hidden]` 会失效

作者样式里的 `display: flex` **压过**浏览器默认的 `[hidden] { display: none }`。
所以 `.pick-bar[hidden]` / `.asset-modal[hidden]` / `.wb-modal[hidden]`
各自必须显式 `display: none`。

**这个 bug 真的发布过**：带 `hidden` 的弹窗仍然 `display:flex`，
一层 74% 不透明度的遮罩看不见地盖住整页，**吃掉每一次点击**。
它逃过了当时的自动化检查，因为脚本用的是 `element.click()`（直接派发事件、**不做命中测试**）
—— 最后是靠 `document.elementFromPoint()` 查出来的。

## 七、界面直跑命令（`js/actions.js`）

三个入口，一份实现：

| 入口 | 形态 |
|---|---|
| 找照片 | "这个词还没准备过"空态里的「立即准备」按钮 |
| 人物 | "还没有检出人脸 / 还没算特征"空态里的按钮 |
| 维护 | 常驻面板（完整列表）+ 弹窗（顺手挑一条） |

三条路径都汇到 `submitAction()` —— *"三处各写一遍必然出现'同一件事三种反馈'"*。

要点：

- 目录 `/api/actions` 拉一次就缓存（一次会话内不变）；
- 提交只带 `action id` 与（可选的）`query`；**用不用 query 由服务端判断**；
- 进度用自适应轮询；失败时把 `job.error` 的**最后几行**弹给用户
  —— *"失败原因里带命令自己的最后几行输出 —— 直接给用户看，不要吞掉"*；
- 缺依赖的动作**不隐藏**，标成「缺依赖」并列出缺什么；
- 目录晚到时只**原地**改 `disabled`/`title`，不重建 DOM
  —— *"重建会让滚动位置跳走（而且看起来像页面闪了一下）"*；
- 所有插值都过 `escapeHtml()`（含 `data-*` 属性）。

## 八、视觉纪律（产品底线，PRD §9.2 LOCKED）

> **不做任何"评分 / 星级 / 推荐 / 匹配度大字"的视觉语言。**
> 金色 = 高亮，**不是"更好"**；酒红 = 危险，**不是"更差"**。

具体表现：

- 没有星级、没有进度环、没有"匹配度 87%"的大字；
- 相似度**刻意做得极小且灰**（`--ink-text-3`），作用是"为什么它在前面"的可核对性，
  不是给人比优劣的；
- 人物页的判据是机器用的数 → 用等宽字体，**不做大字强调**（"大字就成了'分数'"）；
- 人物三态靠**边框**区分（不是靠颜色深浅表示好坏）；
- 状态徽标只表达"你把这张放到哪一档"；
- 学习栏的措辞：写"你选了几张 / 删了几张"，**绝不写**"模型置信度 / 准确率 / 评分"；
- 唯一允许的百分比进度条是**后台任务**的那一条。

### 两条"反 AI 感"的具名禁令

1. **卡片/提示左侧的 3px 色条** —— 被认为是最容易被认出来的 AI 生成痕迹，
   在本仓库被**移除四次**（`.notice`、`.grp.is-active`、`.person-profile`、`.asset-path`）。
   品牌签名（"当前项"）靠**描边 + 同色系淡底**同样成立，而且更统一。
2. **零默认样式**（DNA P0）—— ul/ol/blockquote/table/button/input/链接全部品牌化；
   连复选框都是自己画的。
