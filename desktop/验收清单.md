# 绿色包验收清单（人工点一遍）

对象：`desktop\_dist\PhotoOS-0.1.0-win64.zip`
目的：把"服务起得来"升级为"用户能从头用到尾"。

> 每条前面留空行：通过打 `x`，有问题写一行现象。
> 全程约 5–10 分钟（导入只挑 20 张，别用整库）。

前置：

- [ ] 把 zip 解压到**另一个路径**（例如 `C:\PhotoOS-test\`），不要用源码目录
- [ ] 若旧实例还开着，先退出（Electron 单实例：同用户目录只能跑一份）
- [ ] 需要并行对比时用：`PhotoOS.exe --user-data-dir=C:\PhotoOS-test\userdata`

---

## A. 启动（30 秒）

- [ ] 双击 `PhotoOS.exe`，先出现**启动小窗**（品牌 + "正在启动本地服务…" + 金色进度条）
- [ ] 1–3 秒后主窗口出现，启动小窗消失
- [ ] 右上角显示版本 / schema，没有 `undefined`、没有空白
- [ ] 首次启动时数据根是空的（`照片库` 页没有照片）—— 这是预期，不是丢数据

## B. 数据根（设置）

- [ ] 维护页 →「数据根」显示当前路径、"库 0 个 / 照片 0 张"、可写
- [ ] 填入一个**已有库**的路径 → 点「检查这个目录」→ 提示"已有 PhotoOS 库 · N 个库 / M 张照片"
- [ ] 点「使用已有库」→ 提示已保存、要求重启
- [ ] 退出重开 → 数据根变成刚才那个，照片出现在库里
- [ ] 反例：填一个没有 `photoos.db` 的目录 → 「使用已有库」按钮是灰的，只能「新建空库」

## C. 添加照片库

- [ ] 照片库标题旁有「+ 添加…」
- [ ] 点开对话框 → 桌面壳里「选目录…」能调起系统目录选择器
- [ ] 选一个装照片的目录 → 添加 → 侧栏出现该库，状态"在线"
- [ ] 同一目录**再添加一次** → 提示"已登记过这个库"，不报错、不重复
- [ ] 去那个目录看：多了一个 `.photoos\library.json`（这是 PhotoOS 唯一写进去的东西）

## D. 导入 → 分组 → 精选

- [ ] 维护页 →「导入新照片」选一个小目录（20 张左右）→「预演」看到数量
- [ ] 「确认执行」→ 导入卡片底部出现"导入任务 #N"，进度百分比在动
- [ ] 任务跑完 → 精选页出现场景；`照片库` 页能看到缩略图
- [ ] 精选页选一个场景 → 能 `Space` 切换、`1/2/3` 打标
- [ ] 返回列表后，刚才的选择还在（刷新一次仍在）

## E. AI 组件（可选，按需）

- [ ] 维护页 →「AI 组件」列出 6 项，未装的显示"安装"，依赖未满足的按钮是灰的并写明缺谁
- [ ] 点 `ONNX Runtime（CPU）` 安装 → 状态变"安装中…"→"已安装"
- [ ] 点 `CLIP 视觉模型`（335 MB）→ 下载完成后状态变绿
- [ ] 两个镜像输入框旁边「测试」返回"连通"
- [ ] 找照片页 → 空态显示「一键准备」（**不应出现任何命令行**）

## F. 迁移与诊断

- [ ] 维护页 →「立即迁移」→ 显示 `版本 9 → 9` + 备份路径，没有报错
- [ ] 「库状态」下方诊断区显示：数据根 / 数据库大小 / 服务地址 / 日志目录 / 库与照片数
- [ ] 点「复制诊断信息」→ 剪贴板里是纯文本（不含照片文件名）

## G. 退出

- [ ] 点窗口 × → 收进托盘（后端仍在跑，任务不中断）
- [ ] 托盘右键 →「退出」→ 进程树清空（任务管理器里没有残留 `python.exe`）
- [ ] 侧栏「系统 → 退出」→ 先弹确认，确认后同样清空
