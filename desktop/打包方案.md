# PhotoOS 打包方案（发给认识的人）

2026-10-18 · 依用户五项决策定稿：**只给熟人 · AI 默认不装 · 不内置 ffmpeg · 不做自动更新 · 接受 Win10 1809+**

---

## 1. 目标与非目标

**目标**：一个压缩包，解压双击就能用；对方机器上**不需要装 Python、不需要管理员权限、不需要联网**。

**非目标（本轮明确不做）**：代码签名、自动更新、NSIS 安装包、内置 AI、内置 ffmpeg、多用户/服务化。

> 为什么不做安装包：本机 `electron-builder 26 + pnpm 11` 打 NSIS 会报 `No JSON content found in output`（见 README）。熟人分发用**绿色包**更省事——不解压到 Program Files，不触发 UAC，绕过这个已知 bug。将来要安装包时，目录结构不用改，只是外面多套一层。

## 2. 交付物

```
PhotoOS-<版本>-win64.zip        ≈ 300–360 MB
  PhotoOS.exe                   Electron 主程序
  resources/app/                壳代码（main.js / preload.js / lib / assets）
  runtime/python/               embeddable CPython 3.12 + 全部依赖
  runtime/backend/photoos/      后端源码（含 web 前端）
  首次运行说明.txt               三步：解压、双击、选库目录
  BUILD.txt                     版本 / 构建时间 / sha256
```

解压到**任意可写目录**（桌面、D 盘都行），不写注册表、不装服务。

## 3. 数据放哪

| 项 | 位置 | 说明 |
|---|---|---|
| 数据库 / 缩略图 / 备份 | `%LOCALAPPDATA%\PhotoOS\data` | 默认值；用户可在首次向导里改 |
| 照片本体 | 用户自己的目录 | **只读**，永不移动/改名/删除（产品铁律） |
| 配置 | `%LOCALAPPDATA%\PhotoOS\data\config.json` | 显式写 `data_root`，避免"空库" |
| 日志 | `%LOCALAPPDATA%\PhotoOS\data\logs` | 供熟人发回来排障 |

⚠️ 打包后没有 `photoos.toml`，**不显式写 data_root 就会落到别处**，用户看到的是空库——这条必须在首次向导里做死。

## 4. 构建流水线（`desktop/build-portable.ps1`）

```
1) 下载 python-3.12.x-embed-amd64.zip      → runtime/python/
2) 改 python312._pth：加 "." 和 "Lib\site-packages"
3) 装 get-pip（嵌入版不带 pip）
4) pip install --target runtime/python/Lib/site-packages -r requirements.lock --only-binary=:all:
5) 复制 backend/photoos → runtime/backend/photoos（不含 __pycache__ / tests）
6) electron-builder --win --x64 --dir          # 只出解包目录，不碰 NSIS
7) 组装 + 写 BUILD.txt + Compress-Archive
```

要点：

- **`--only-binary=:all:`**：任何包要现场编译就说明这个方案在这台机器上不可复制，直接失败。
- **依赖锁**：`requirements.lock` 固定版本 + 哈希，避免"今天能打、下周打出来不一样"。
- **Python 版本**：取 3.12 最新补丁版；嵌入版自带 `vcruntime140.dll`，对方**不需要**装 VC++ 运行库。
- 不用 PyInstaller：uvicorn/pydantic/lxml 的隐藏导入坑多，且被杀软误报的概率更高。

## 5. 首次运行（壳里做，不由用户做）

1. 检测 8760 是否已被占用 → 占用则接管/提示，**绝不并起第二个 uvicorn 写同一个库**；
2. 数据目录：默认 `%LOCALAPPDATA%\PhotoOS\data`，给"选择已有库目录"（迁移/换机场景）；
3. 生成 `config.json`（含 `data_root`），首次 `photoos init`；
4. 启动后端（`runtime/python/python.exe -m photoos serve`），轮询 `/api/health`；
5. 成功开窗；失败弹窗里给**可复制**的诊断（版本、schema、日志尾部 20 行）。

## 6. AI 与视频的降级（已定的行为）

- **AI 没装**：人物/语义搜索入口显示"需要安装 AI 组件"，其余功能照常（现状即如此，不改）。
- **AI 安装**：应用内说明"另装一个 Python 环境 + 下载模型"，不塞进 zip。
- **ffmpeg 没装**：视频只能索引元数据，缩略图显示占位图；不报错、不崩。

## 7. 已知风险与对策

| 风险 | 对策 |
|---|---|
| 杀软误报（内嵌 `python.exe`） | 提供 sha256 + 一句话说明；必要时让熟人手动"添加信任" |
| 中文 / 空格 / 长路径 | 构建后在一台中文用户名机器上跑一遍导入 + 缩略图 |
| 端口 8760 被浏览器版占用 | 壳自动换端口（已有逻辑），并在窗口标题显示实际端口 |
| 库在 OneDrive 同步目录 | 说明文档里明确"不建议"，SQLite + 同步会锁冲突 |
| 升级导致 schema 迁移失败 | 升级前自动备份；失败回滚到备份（迁移逻辑本身已有） |

### 过程中踩到并修掉的坑（都会在别的机器上复现）

1. **`._pth` 隔离**：embeddable Python 只要有 `._pth`，`PYTHONPATH` 就完全失效。必须把
   `..\backend` 和 `Lib\site-packages` **写进 `._pth`**，否则永远 `No module named photoos`。
2. **electron-builder 走不通**：`26 + pnpm 11` 在收集 node_modules 时报
   `No JSON content found in output`，连 `--dir` 也过不去。改为**直接复制 electron dist**
   + 自己的 `resources/app`，效果等价且少一层工具链（壳没有运行时 node 依赖）。
3. **`ELECTRON_RUN_AS_NODE`**：在 Electron 环境（如 DSH 自身的终端）里启动 `PhotoOS.exe` 时，
   它会以 Node 模式跑并报 `Cannot read properties of undefined (reading 'setName')`。
   **不是包坏了** —— 双击（不继承该变量）正常。测试脚本里要先 `Remove-Item Env:\ELECTRON_RUN_AS_NODE`。
4. **PS 5.1 的编码**：`.ps1` 必须存 UTF-8 with BOM；`Get-Content -Raw` 读 `package.json`
   会按 GBK 解码把中文注释读坏，要用 `[IO.File]::ReadAllText(..., UTF8)`。
